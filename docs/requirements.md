# 要件定義書

## 1. 背景と目的

日々の収入・支出を紙やスプレッドシートで管理していると、過去の記録を探しにくく、入力も手間がかかる。
本アプリは、個人の収支を **記録・検索・整理** できる Web アプリケーションを提供し、家計の把握を容易にすることを目的とする。

初級者最終課題として、以下の一連の開発プロセスを実践することも目的に含む。

- 要件定義 → 技術選定 → 設計 → 実装 → デプロイ
- GitHub Issue / PR ベースの開発運用
- Terraform による AWS へのインフラ構築とデプロイ

## 2. スコープ

### 2.1 対象範囲（作るもの）

| 区分 | 内容 |
| --- | --- |
| 収支レコード管理 | 一覧表示、検索、追加、更新、並び替え、一括更新、削除 |
| カテゴリ | あらかじめ用意した固定カテゴリから選択する |
| 画面 | 単一ページの一覧画面 + 入力モーダル |
| データ永続化 | PostgreSQL に保存する |
| デプロイ | AWS（EC2 + RDS + S3）上で動作する |

詳細な機能定義は [features.md](./features.md) を参照。

### 2.2 対象外（作らないもの）

- ユーザー認証・ログイン機能（**単一ユーザー前提**。全データを 1 人分として扱う）
- 複数ユーザーによるデータ分離、権限管理
- 複数通貨対応（日本円のみ）
- レシート画像の読み取り（OCR）、銀行・カード明細の自動取り込み
- グラフによる集計・可視化、予算設定とアラート
- カテゴリのユーザー自身による追加・編集（初期データとして固定）
- スマートフォンアプリ、CSV インポート／エクスポート
- 通知機能（メール・プッシュ）

## 3. 用語定義

| 用語 | 説明 |
| --- | --- |
| 収支レコード（レコード） | 1 件の収入または支出の記録。日付・カテゴリ・金額・メモを持つ |
| カテゴリ | レコードの分類。「食費」「給与」など。収入用と支出用がある |
| 収支区分 | カテゴリが収入（INCOME）か支出（EXPENSE）かを表す種別 |
| 表示順 | 一覧上での並び順。ドラッグ&ドロップで変更でき、サーバに永続化される |
| 一括更新 | 一覧で複数のレコードを選択し、まとめて内容を変更する操作 |

## 4. 利用者と利用シーン

- 利用者: 家計を管理したい個人 1 名
- 利用シーン:
  - 買い物や給与の受け取りがあったとき、その場でレコードを追加する
  - 月末に期間で絞り込み、その月の支出を確認する
  - カテゴリを付け間違えた複数件を、まとめて正しいカテゴリに直す
  - よく見たい行を一覧の上のほうに並び替えておく

## 5. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 対応ブラウザ | 最新版の Google Chrome（PC）。他ブラウザは動作保証しない |
| 画面幅 | 1280px 以上の PC 画面を基準とする。スマートフォン対応は必須としない |
| 性能 | レコード 1,000 件程度で、一覧取得 API のレスポンスが 1 秒以内 |
| データ永続化 | PostgreSQL に保存し、アプリ再起動後もデータが保持される |
| 可用性 | 常時稼働は要件としない。学習用途のため単一 EC2 インスタンス構成で可 |
| セキュリティ | 認証なしのため、公開範囲は自身の検証用に限定する。SQL インジェクション対策として、DB アクセスはプレースホルダ経由とする |
| 入力値検証 | フロントエンドとバックエンドの両方でバリデーションを行う（詳細は [features.md](./features.md)） |
| 構成管理 | インフラは Terraform でコード化し、`terraform destroy` で撤去できる |
| ドキュメント | 実装と docs の内容に差異が出たら docs を更新する（手順7の品質監査で確認） |

## 6. 前提条件・制約

- 通貨は日本円のみ、金額は小数を扱わない整数とする
- 時刻は扱わず、レコードは日付（年月日）単位で記録する
- タイムゾーンは Asia/Tokyo を前提とする
- 技術スタックの詳細は `tech-stack.md`（手順3）で確定する
