## 1. このアプリで解決すること

「今月はこの金額までに抑えたい」と決めていても、実際にいくら使ったかを把握していないと、気づいたときには使いすぎています。レシートや支払い履歴を見返すだけでは、**予算に対してあといくら使えるのか**が分かりません。

本アプリは、**決めた予算の範囲内で生活できているかを一目で把握できる**ことを目的としています。

想定するご利用の流れは次のとおりです。

```
  ① 月の予算を決めて登録する      →「9月は80,000円まで」
  ② 支払いのたびに記録する        →「9/25 食費 1,280円」
  ③ 残額を確認する                →「残り27,700円」 ★ここが最重要
  ④ 内訳を見て使いすぎに気づく    →「食費が32,100円…多いな」
```

**③の「あといくら使えるか」に答えること**を、本アプリの中心的な価値と位置づけています。単なる記録の保管庫ではなく、判断のための道具としてお使いいただくことを想定しています。

この方針は画面設計にも反映しており、**残額を画面内で最も目立つ要素**として配置します。

## 2. 誰がどう使うか

**ご利用者**: 予算を決めて家計を管理したい個人のお客さま 1 名

**ご利用シーン**:

| 場面 | 操作 |
| --- | --- |
| 月初 | その月の予算を登録する |
| 買い物・給与の受け取り時 | その場で 1 件記録する |
| 買い物の前 | 残額を確認し、使ってよい金額を判断する |
| 月の途中 | 内訳を見て、どのカテゴリで使いすぎているかを把握する |
| レシートをまとめて入力した後 | 日付が今日になっている複数件を、まとめて正しい日付に直す |

## 3. 画面と操作の流れ

画面は**1 ページ構成**です。ダッシュボードを開いたままで、入力や設定は重ねて表示されるウィンドウ（モーダル）で行います。画面が切り替わらないため、残額を見ながら操作を続けられます。

| 画面 | 役割 |
| --- | --- |
| ダッシュボード | 起点となる画面。残額の確認と明細の管理 |
| 収支入力ウィンドウ | 1 件の登録・修正 |
| 削除確認ダイアログ | 削除前の確認 |
| 予算設定ウィンドウ | その月の予算の登録・変更 |

```
  ┌─────────────────────────────┐
  │  ダッシュボード             │  ← 常に表示
  │  ・対象月の切り替え         │
  │  ・予算／使用額／残額       │ ★最も大きく表示
  │  ・カテゴリ別の内訳         │
  │  ・明細一覧（検索・絞り込み）│
  └─────────────────────────────┘
        │  ＋追加／編集     │  予算を設定     │  削除
        ▼                   ▼                 ▼
   収支入力ウィンドウ   予算設定ウィンドウ  削除確認ダイアログ
        └───────── 保存／キャンセルで戻る ─────────┘
```

## 4. 提供する機能

| 機能 | お客さまにとっての意味 |
| --- | --- |
| 月次サマリー | その月の予算・使用額・残額・使用率が一目で分かる。予算を超えると警告色で表示される |
| 予算の設定 | 月ごとに「ここまで」という上限額を登録・変更できる |
| カテゴリ別の内訳 | どのカテゴリにいくら使ったかを、金額・割合・バーで確認できる |
| 月別の明細一覧 | その月に記録した収入・支出を新しい順に一覧できる。前月・翌月に切り替えられる |
| 収支の追加 | 日付・カテゴリ・金額・メモを入力して 1 件記録する |
| 収支の編集 | 記録した内容をあとから修正できる |
| 収支の削除 | 誤って記録したものを、確認のうえ削除できる |
| 検索・絞り込み | 期間・カテゴリ・メモのキーワードで明細を絞り込める |
| まとめて修正 | 複数件を選んで、日付やカテゴリを一度に直せる。レシートのまとめ入力後の修正を想定。1 回の操作で 500 件までを対象にできます |

カテゴリは、日常的な記録をカバーする **13 種類**をあらかじめご用意します。ご利用開始後の追加・変更はできませんので、この内容でよいかご確認ください。

| 区分 | カテゴリ |
| --- | --- |
| 支出（9種） | 食費 / 日用品 / 交通費 / 住居費 / 水道光熱費 / 通信費 / 娯楽費 / 医療費 / その他 |
| 収入（4種） | 給与 / 賞与 / 副収入 / その他収入 |

金額は日本円の整数のみ、記録の単位は日付（年月日）で、時刻は扱いません。1 件あたりの上限は 9,999,999 円、予算の上限は 99,999,999 円です。

### ご了承いただきたい動作

お使いいただくうえで、あらかじめお伝えしておく仕様です。

| 項目 | 動作 |
| --- | --- |
| 同じ内容の重複登録 | 重複チェックは行いません。同じ日・同じカテゴリ・同じ金額を複数登録できます（同日に同じ店で 2 回お買い物をされる場合があるため） |
| 削除したデータ | **元に戻せません。** ゴミ箱や取り消し操作はないため、削除前に必ず確認画面を表示します |
| 支出と収入の入れ替え | 記録済みの支出を収入のカテゴリに変更することはできません（残額の計算結果が大きく変わるため）。変更が必要な場合は削除して登録し直してください |
| 予算 0 円 | 「今月は使わない」という設定として登録できます。この月に支出があると超過として表示されます |
| 未来の日付 | 登録できます。翌月に切り替えて予定を記録する使い方を想定しています |
| 複数のタブで同時に開いた場合 | 後から保存した内容が有効になります。先の変更は警告なく上書きされますので、1 つのタブでのご利用をお願いします |
| データの保存期間 | 期限は設けません。古い記録が自動で消えることはありません |

## 5. 今回作らないもの

家計簿アプリとして考えられる機能を洗い出したうえで、**§1 の目的（予算に対する残額の把握）への寄与**を基準に絞り込みました。以下は、検討のうえ今回の範囲外としたものです。ご要望があれば次期以降の候補として改めてご相談させてください。

### 目的への寄与が小さいもの

| 機能 | 今回含めない理由 |
| --- | --- |
| 明細の手動並び替え（ドラッグ＆ドロップ） | 家計簿の明細は日付順で見るのが自然で、任意の順序を付ける意味がありません。また絞り込み中は全体の順序が保てず、操作できない理由がお客さまに伝わらないため、かえって使いにくくなると判断しました |
| 日付順・金額順の並べ替え | 月別表示とカテゴリ別内訳があれば、残額の把握という目的は達成できます |
| カレンダー形式の表示 | 明細一覧と役割が重なります |

### 有用だが、今回の範囲外とするもの

| 機能 | 今回含めない理由 |
| --- | --- |
| カテゴリ別の予算設定 | 月全体の予算だけで「あといくら使えるか」にはお答えできます。カテゴリごとの設定は設定画面とデータ構造が複雑になるため、まずは月全体のみとします |
| グラフによる可視化（円グラフ・推移） | 内訳は金額・割合・バーの表で把握いただけるため、まずは表形式でご提供します |
| 前月との比較 | 有用ですが、残額の把握という中心的な価値には直接つながりません |
| カテゴリの追加・変更・削除 | ご用意する 13 種類で日常的な記録をカバーできる見込みです。管理画面を設ける費用に対して効果が見合わないと判断しました |
| 定期支出の自動登録（家賃・サブスクリプション） | 入力の手間は減りますが、自動生成のタイミング制御など決めるべきことが多く、今回は範囲外とします |
| よく使う入力のテンプレート | 同様に、入力補助は今回の範囲外とします |
| CSV の入出力 | 他ツールとの連携は今回の目的に含まれません |

### ご利用の前提により含めないもの

| 機能 | 今回含めない理由 |
| --- | --- |
| ログイン機能、複数名でのデータ分離、家族共有 | **ご利用者 1 名**を前提としています。リスクと対処は §6 をご参照ください |
| 日本円以外の通貨 | 日本円のみとします |
| レシート画像の読み取り、画像の添付 | 実装の規模が大きく、目的への寄与が限定的です |
| 銀行・カード明細の自動取り込み | 外部サービスとの連携は今回の範囲外です |
| 支払い方法（現金／カード）の記録、タグ付け | 分類の軸を増やすと入力と集計が複雑になります |
| スマートフォンアプリ、通知機能 | 今回の範囲外です |

## 6. 前提・制約とリスク

本アプリは**ご利用者 1 名・ご自身の環境からのご利用**を前提とした構成です。そのため、一般公開される Web サービスとは前提が異なります。以下をご確認・ご了承いただいたうえで進めさせていただきたく、ご説明します。

| 前提 | それによるリスク | 今回の対処 | 将来の拡張 |
| --- | --- | --- | --- |
| ログイン機能を設けない | URL を知った第三者がデータを閲覧・変更できる | **画面・サーバーのいずれについても**、接続元をお客さまのご利用環境の IP アドレスに限定します。データベースは外部から直接接続できない非公開のネットワークに配置します | ログイン機能の追加。全機能に影響が及ぶため、別途お見積りのうえご相談させてください |
| 通信を HTTPS で暗号化しない | 通信内容を第三者に傍受される可能性がある | 上記のとおり接続元を限定した環境でのご利用を前提とします | 独自ドメインの取得と HTTPS 化 |
| ご利用者は 1 名 | 複数名で同時にお使いになると、双方のデータが同じ一覧に混在する | 1 つの環境につき 1 名でのご利用をお願いします | ご利用者ごとのデータ分離 |
| サーバーは 1 台構成 | サーバーが停止している間はご利用いただけない | 24 時間365日の稼働は前提としません。停止時は個別にご連絡のうえ復旧対応します | 複数台による冗長化構成（費用が増加します） |
| 対応環境は PC の Google Chrome（最新版） | 他のブラウザやスマートフォンでは表示が崩れる可能性がある | 画面幅 1280px 以上の PC でのご利用を前提とします | スマートフォン向けの画面対応 |

## 7. 品質の考え方

「動くこと」だけでなく、**どうやって確認するか**をあらかじめ決めています。主なものを抜粋します。

| 観点 | お約束する水準 | 確認方法 |
| --- | --- | --- |
| 表示速度 | 記録が 1,000 件ある状態でも、残額と明細の取得が 1 秒以内 | 1,000 件のデータを投入して実測します |
| 画面の表示 | ダッシュボードを開いてから残額が表示されるまで 2 秒以内 | ブラウザの計測機能で確認します |
| データの保持 | サーバーを再起動しても記録は失われません | 再起動の前後でデータが残ることを確認します |
| まとめて修正・まとめて削除の安全性 | 対象に問題が 1 件あった場合、**一部だけ書き換わったり、一部だけ消えたりすることはありません**（全件成功か、全件そのまま） | 自動テストで確認します |
| 入力の誤り | 金額・日付・カテゴリの誤りは、保存される前にその場でお知らせします。画面側だけでなくサーバー側でも検証します | 自動テストと画面操作の両方で確認します |
| 機能の動作確認 | §4 の全機能について、あらかじめ定めた合否条件を自動テストとして用意します | テストがすべて成功することを確認します |
| 修正による影響 | 機能を追加・修正するたびに、**それまでの全機能のテストを自動で実行**します。既存の機能が意図せず壊れた状態のまま先に進むことはありません | テストが成功しない限り変更を取り込めない仕組みにしています |

品質に関する取り決めは 40 項目を定義しており、それぞれに確認方法を紐づけています。全項目は[非機能要件](./non-functional.md)をご参照ください。

## 8. リリース計画

6 つの段階に分けて進めます。**各段階の終わりに、その時点で確認いただけること**を明記しています。ご都合のよいタイミングでご確認いただき、次の段階に進む形を想定しています。

| 段階 | 内容 | この時点でご確認いただけること |
| --- | --- | --- |
| 1 | 土台の準備 | （内部作業のみ。ご確認いただくものはありません） |
| 2 | データの保存場所の用意 | カテゴリ 13 種類が登録されていること |
| 3 | 機能の本体（サーバー側） | §4 の全機能が、定めた合否条件どおりに動くこと（自動テストの結果でご報告します） |
| 4 | 画面の作成 | 画面イメージと同等の見た目。**残額が最も目立つ**こと、予算超過時に警告色になること |
| 5 | 画面と機能の接続 | 予算設定 → 支出を追加 → 残額が減る → 削除 → 残額が戻る、という一連の流れが実際に動くこと。**この段階で通しでの動作確認をお願いします** |
| 6 | 公開環境への配置 | ブラウザから URL を開いてご利用いただけること |

具体的な日程は、ご確認のお時間を含めて別途ご相談させてください。

## 9. 運用と費用

### 稼働とご利用時間

24 時間365日の連続稼働は前提としていません（§6）。ご利用されない期間はサーバーを停止し、費用を抑えることもできます。

### 費用の目安

| 項目 | 内容 |
| --- | --- |
| 構成 | クラウド（AWS）上のサーバー 1 台、データベース 1 台、画面配信用のストレージ |
| 月額の目安 | 最小構成のため、**無料利用枠の範囲内に収まる想定**です。枠を超える場合は、事前に概算をお知らせします |
| 費用が発生する条件 | サーバーとデータベースは**起動している時間に応じて**課金されます。停止していれば課金は最小限です |
| 停止・撤去 | ご利用終了時は、構成をまとめて削除できるようにしています（作成した資源が残り続けて課金されることはありません） |

### データのバックアップ

データベースの自動バックアップを有効にします（保持期間は標準設定）。ただし、**実際に復元して動作を確認する作業は今回の範囲に含めません**。復元が必要な事態が生じた場合は個別に対応させていただきます。

### 障害時の対応

| 項目 | 内容 |
| --- | --- |
| ご連絡方法 | ご指定の連絡手段（別途取り決め） |
| 対応時間 | 営業時間内での対応とし、即時復旧はお約束しません |
| 対応範囲 | アプリの不具合、サーバー停止時の再起動 |
| 監視 | 自動監視・自動通知は今回設けません。異常にお気づきの際はご連絡ください |

## 10. 検収と変更管理

### 検収の進め方

§4 の各機能について、**あらかじめ合否条件を文書化**しています。この条件が、そのまま検収項目になります。

1. 当方で自動テストを実行し、結果をご報告します
2. 段階 5 の時点で、お客さまに画面上での通し確認をお願いします
3. 段階 6（公開環境）で、同じ内容を公開先の URL でご確認いただきます
4. ご指摘事項を一覧化し、修正・再確認のうえ完了とします

合否条件の詳細は[機能一覧](./features.md)に機能ごとに記載しています。

### 仕様変更のお取り扱い

| 段階 | お取り扱い |
| --- | --- |
| 本資料のご確認中 | 内容に反映し、版数を上げて再提出します（追加費用なし） |
| 開発の段階 1〜4 | 影響範囲と追加期間をお見積りのうえ、ご判断いただきます |
| 段階 5 以降 | 原則として次期対応とし、緊急のものは個別にご相談させてください |

### 版数の管理

本資料はご確認・ご指摘のたびに版数を上げ、**改訂履歴**（§11）に変更内容を記録します。最新版がどれか分からなくなることを防ぐため、常に版数でご確認ください。

## 12. 用語

| 用語 | 説明 |
| --- | --- |
| 収支レコード（レコード） | 1 件の収入または支出の記録。日付・カテゴリ・金額・メモを持ちます |
| カテゴリ | レコードの分類。「食費」「給与」など。収入用と支出用があります |
| 予算 | その月に使ってよい支出の上限額。月ごとに 1 つ設定します |
| 残額 | 予算からその月の支出合計を引いた額。マイナスの場合は予算超過です |
| 対象月 | 画面が現在表示している年月。前月・翌月に切り替えられます |

**予算の対象は支出のみ**です。収入は残額の計算には含めません（例: 予算 80,000 円の月に給与 300,000 円を記録しても、残額は増えません）。
