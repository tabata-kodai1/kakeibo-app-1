# 非機能要件

[requirements.md](./requirements.md) の目的（**決めた予算の範囲内で生活できているかを一目で把握できる**）を満たすために、機能そのもの以外に満たすべき条件を定義する。

## 方針

本アプリは **単一ユーザー・学習用途** であり、常時稼働や多人数利用を前提としない。そのため非機能要件は次の基準で絞り込んだ。

| 優先する | 優先しない |
| --- | --- |
| 実装と検証を完走できること | 高可用性・冗長化 |
| 目的（残額の即時把握）を損なわない応答速度 | 大規模データ・高負荷への耐性 |
| データが失われないこと | 障害からの自動復旧 |
| 撤去できること（コスト管理） | 運用の自動化・監視基盤 |

各項目には **確認方法** を必ず添える。確認できない要件は書かない。

### セキュリティ

認証を持たないことを前提に、**接続元とネットワークを絞ること**で代替する。

| ID | 分類 | 要件 | 確認方法 |
| --- | --- | --- | --- |
| N-08 | 公開範囲 | 認証がないため、接続元 IP を自身の環境に限定する。**API は EC2 のセキュリティグループで、画面はフロント配信用 S3 バケットのバケットポリシー（`aws:SourceIp`）で制限する**。セキュリティグループは S3 には効かないため、両方が必要 | Terraform のコードレビュー、外部からの接続不可の確認（API・画面の両方） |
| N-09 | DB アクセス | DB アクセスはすべて ActiveRecord 経由とし、SQL 文字列に値を直接連結しない | Brakeman（CI で実行）＋コードレビュー（`ILIKE` 等の生 SQL はプレースホルダ使用） |
| N-10 | ネットワーク | RDS はプライベートサブネットに置き、EC2 のセキュリティグループからのみ接続を許可する | Terraform のコードレビュー |
| N-11 | 機密情報 | 接続情報・鍵・パスワードはソースにハードコードせず環境変数から読み込む。`master.key` / `.tfvars` / `.env` は Git にコミットしない | `.gitignore` の確認、`git log -p` での混入確認 |
| N-12 | CORS | 本番の許可オリジンは S3 の静的サイトドメインのみとし、環境変数で設定する（ワイルドカード不可） | `rack-cors` の設定確認 |

| ID | 分類 | 要件 | 確認方法 |

| N-17 | 構成管理 | インフラは Terraform でコード化し、`terraform apply` で再構築、`terraform destroy` で撤去できる | 実際に destroy → apply を 1 回通す |

| N-37 | 環境差異 | ローカルと本番で PostgreSQL・Ruby のメジャーバージョンを一致させる | `docker-compose.yml` と RDS の設定確認 |

## 性能の確認手順（N-03）

「1,000 件で 1 秒以内」は、以下の手順で一度だけ測る。

1. seed タスクでレコードを 1,000 件投入する（12 か月ぶん、カテゴリ・金額はランダム）
2. `GET /api/summary?month=YYYY-MM` と `GET /api/entries?month=YYYY-MM` を 5 回ずつ実行する
3. Rails のログに出る処理時間、および `curl -w "%{time_total}"` の値を記録する
4. 1 秒を超える場合は、[database.md のインデックス](./database.md#インデックス)が効いているかを `EXPLAIN` で確認する

前提として、月次サマリーとカテゴリ別集計は**アプリ側でループせず SQL の集計で求める**（[tech-stack.md](./tech-stack.md#dbアクセス-activerecord)）。1,000 件規模ではインデックスが効いていれば問題にならない想定で、この測定はその確認にあたる。

## 対象外とする非機能要件

| 項目 | 外す理由 |
| --- | --- |
| 認証・認可、パスワード管理 | 単一ユーザー前提のため機能要件から外しており、非機能側でも扱わない（代わりに N-08 で接続元を制限する） |
| HTTPS / 独自ドメイン | ACM・CloudFront・Route 53 の追加が必要になり、学習用途の構成に対して要素が多い。検証は自身の環境からのみ行う前提で HTTP とする |
| リストア手順の検証 | バックアップの取得自体は要件とする（N-40）が、実際に復元して動作を確認する工程は行わない |
| 監視・アラート（CloudWatch アラーム等） | 常時稼働が要件外であり、障害に即応する必要がない |
| 負荷試験・同時アクセス性能 | 利用者は 1 名。同時実行の競合は発生しない |
| 多言語対応・アクセシビリティ準拠（WCAG 等） | 日本語・単一利用者向けのため。ただしラベルとフォーカス可能な要素は素直な HTML で書く |
| スマートフォン・タブレット対応 | N-02 のとおり PC 前提 |
| CD（自動デプロイ） | デプロイは手動手順（[plan.md](./plan.md) フェーズ6）で行う。GitHub と AWS の OIDC 連携などの設定が増える一方、デプロイ先は単一 EC2 であり見合わない。**CI（PR でのテスト・lint の自動実行）は N-16・N-33・N-34・N-35 のため採用する** |
