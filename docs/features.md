## 共通仕様

### API 一覧

| メソッド | パス | 機能 |
| --- | --- | --- |
| GET | `/api/summary?month=YYYY-MM` | 月次サマリーとカテゴリ別内訳の取得 |
| GET | `/api/entries` | 明細一覧の取得（月指定・検索条件つき） |
| POST | `/api/entries` | レコード追加 |
| PUT | `/api/entries/{id}` | レコード更新 |
| PATCH | `/api/entries/bulk` | 複数レコードの一括更新 |
| DELETE | `/api/entries/{id}` | レコード削除 |
| DELETE | `/api/entries/bulk` | 複数レコードの一括削除 |
| PUT | `/api/budgets/{year_month}` | 予算の登録・更新 |
| GET | `/api/categories` | カテゴリ一覧取得 |

リクエスト／レスポンスの形式は JSON（`application/json`、UTF-8）とする。キーは snake_case。

### レコードの JSON 表現

```json
{
  "id": 1,
  "entry_date": "2026-09-25",
  "category_id": 3,
  "category_name": "食費",
  "category_type": "EXPENSE",
  "amount": 1280,
  "memo": "スーパーで買い物"
}
```

明細の並び順は `entry_date` 降順、同日なら `id` 降順（新しい記録が上）で固定する。ユーザーが並び順を変更する機能は持たない（[requirements.md の対象外](./requirements.md#22-対象外作らないもの)）。

### バリデーション規則

フロントエンド・バックエンドの両方で検証する。

| 項目 | 規則 | エラーメッセージ例 |
| --- | --- | --- |
| `entry_date` | 必須。`yyyy-MM-dd` 形式の実在する日付。**未来日付も許可する**（翌月を開いて予定を記録できるようにするため） | 日付を入力してください |
| `category_id` | 必須。`categories` に存在する ID | カテゴリを選択してください |
| `amount` | 必須。1 以上 9,999,999 以下の整数 | 金額は1以上の整数で入力してください |
| `memo` | 任意。200 文字以内。**改行は含められない**（入力欄は 1 行、一覧では省略表示するため）。空白のみの入力は未入力として扱い `null` で保存する | メモは200文字以内で入力してください（改行を含む場合は「メモに改行は含められません」） |
| `year_month` | 必須。`yyyy-MM` 形式 | 対象月の形式が不正です |
| 予算の `amount` | 必須。0 以上 99,999,999 以下の整数 | 予算は0以上の整数で入力してください |

`amount`（1 件 9,999,999 まで）と予算の `amount`（99,999,999 まで）で上限が異なるのは意図的で、**予算は 1 か月ぶんの支出の合計を受け止める値**のため 1 桁多く取っている。

**金額（`amount`）の型**: JSON の整数のほか、数字だけの文字列（`"1280"`）も整数として受け付ける。小数（`12.5`）、カンマ付き（`"1,280"`）、数字以外を含む文字列、ハッシュ・配列は 400。予算の `amount` も同じ。

### エラーレスポンス

| HTTP ステータス | 発生条件 | ボディ |
| --- | --- | --- |
| 400 Bad Request | バリデーションエラー | `{ "message": "...", "errors": { "amount": "金額は1以上の整数で入力してください" } }` |
| 404 Not Found | 指定 ID のレコードが存在しない。または `/api` 配下に該当するパスがない（存在しないパス、予算の削除など提供しない操作） | `{ "message": "対象のレコードが見つかりません" }` |
| 500 Internal Server Error | 想定外のエラー | `{ "message": "サーバーエラーが発生しました" }` |

`errors` のキーは、リクエストのパラメータ名（クエリ・ボディ・パスのキー）と一致させる。たとえば `month` の形式不正なら `{ "errors": { "month": "対象月の形式が不正です" } }`、`PUT /api/budgets/{year_month}` のパスが不正なら `year_month` がキーになる。項目ごとにメッセージは 1 件で、複数のエラーがあるとき `message` にはそのうち先頭の 1 件を入れる。

`GET /api/summary` と `GET /api/entries` の `month` は、**省略すれば当月、空文字は形式不正（400）** とする。

画面側は 400 のときは該当項目の下にメッセージを表示し、404・500 のときは画面上部にエラーバナーを表示する。

## F-01 月次サマリー

### 概要
**このアプリの中心となる機能。** 対象月の予算・支出合計・残額を計算して表示し、「あといくら使えるか」に答える。

### 入力

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| `month` | `yyyy-MM` | 対象月。省略時は当月 |

```
GET /api/summary?month=2026-09
```

### 出力

```json
{
  "month": "2026-09",
  "budget": 80000,
  "expense_total": 52300,
  "income_total": 250000,
  "remaining": 27700,
  "usage_rate": 65,
  "over_budget": false,
  "entry_count": 12,
  "categories": [
    { "category_id": 1, "category_name": "食費",   "amount": 32100, "rate": 61 },
    { "category_id": 2, "category_name": "日用品", "amount":  8200, "rate": 16 },
    { "category_id": 7, "category_name": "娯楽費", "amount":  8000, "rate": 15 },
    { "category_id": 3, "category_name": "交通費", "amount":  4000, "rate":  8 }
  ]
}
```

`categories` の内容は [F-03](#f-03-カテゴリ別集計) で定義する。

### 計算規則

| 項目 | 計算方法 |
| --- | --- |
| `expense_total` | 対象月の `EXPENSE` カテゴリのレコードの合計 |
| `income_total` | 対象月の `INCOME` カテゴリのレコードの合計 |
| `remaining` | `budget - expense_total`。**収入は含めない**。`budget` が未設定なら `null`（予算がないのに残額を出すと `-expense_total` になり、残額と誤読されるため） |
| `usage_rate` | `expense_total / budget * 100` を整数に丸めた値。`budget` が 0 または未設定なら `null`（0 除算を避けるため） |
| `over_budget` | `budget` が設定済みで `remaining < 0` なら `true`。`budget` が未設定なら常に `false` |
| `entry_count` | 対象月のレコード総件数（収入・支出の両方を含む）。**検索条件の影響を受けない** |

`entry_count` を返すのは、明細一覧の件数表示「**12件中 3件**」の母数（12）を画面が知るため（[S-01 の件数表示](./screens.md#明細一覧)）。`GET /api/entries` は絞り込み後の配列を返すので、絞り込み中はそこから母数を得られない。サマリーは対象月に固定され絞り込みの影響を受けない（[F-08](#f-08-検索絞り込み)）ため、母数の置き場所としてここが適切になる。

**進捗バーの表示規則**（`usage_rate` が `null` のときの扱い）

| `budget` | `expense_total` | バーの表示 |
| --- | --- | --- |
| 未設定 | 問わない | バーを表示せず「予算が未設定です」と案内する |
| 0 | 0 | 0% で表示する |
| 0 | 1 以上 | **100% の警告色**で表示する（予算 0 に対する支出はすべて超過とみなす） |
| 1 以上 | 問わない | `usage_rate` のとおり表示する。100 を超える場合はバーは 100% で止め、残額のマイナス値で超過分を示す |

### 受け入れ条件
- 対象月のレコードだけが集計に含まれること（前月・翌月のデータが混ざらない）
- 予算が未設定の月は `budget`・`remaining`・`usage_rate` が `null` で返り、エラーにならないこと
- 予算が未設定でも `expense_total` と `income_total` は計算されること
- 支出が予算を超えたとき、`remaining` が負の値になり `over_budget` が `true` になること
- レコードが 0 件の月でも、合計 0 でエラーなく返ること
- `entry_count` が対象月の総件数（収入・支出の両方）を返し、明細側の絞り込み条件を変えても値が変わらないこと
- `month` を省略した場合、当月が対象になること（当月の判定はサーバーの Asia/Tokyo の日付による）
- 予算 0 円の月に支出があるとき、`over_budget` が `true` になり、進捗バーが 100% の警告色になること
- 画面上部に、予算・使用額・残額と、使用率を示す進捗バーが表示されること
- 予算超過時は、残額と進捗バーが警告色で表示されること
- 金額が 3 桁区切り（例: `27,700`）で表示されること

## F-02 予算の設定

### 概要
対象月の予算（支出の上限額）を登録・変更する。月ごとに 1 つだけ持つ。

### 入力

```
PUT /api/budgets/2026-09
{ "amount": 80000 }
```

パスの `year_month` が対象月。その月の予算が未登録なら作成し、登録済みなら上書きする。

**予算を削除する API は持たない。** 一度設定した月を「未設定」に戻す手段はなく、変更は上書きのみ（[requirements.md 6.2](./requirements.md#62-予算)）。

### 出力

```json
{ "year_month": "2026-09", "amount": 80000 }
```

新規作成時は 201 Created、更新時は 200 OK を返す。

### 受け入れ条件
- サマリー領域の「予算を設定」から [S-04](./screens.md#s-04-予算設定モーダル) が開くこと
- 予算が未設定の月は入力欄が空、設定済みの月は現在の値が入った状態で開くこと
- 保存すると対象月の予算が登録され、サマリーの残額と進捗バーが即座に更新されること
- 同じ月に対して 2 回目の登録を行うと、**新しいレコードが増えずに上書きされる**こと
- 金額に負数・小数・文字列を入れると 400 になること
- 予算 0 円も登録できること（「今月は使わない」という設定として有効）
- 月を切り替えると、その月の予算が表示されること（月ごとに独立している）

## F-03 カテゴリ別集計

### 概要
対象月の支出を、カテゴリごとに合計して内訳を出す。「何に使いすぎたか」に答える。

### 入力
[F-01](#f-01-月次サマリー) の `GET /api/summary` に含まれる。単独の API は持たない。

画面の初期表示でサマリーと内訳が必ず同時に必要になるため、1 リクエストにまとめてリクエスト数を減らす。

### 出力

```json
"categories": [
  { "category_id": 1, "category_name": "食費",   "amount": 32100, "rate": 61 },
  { "category_id": 2, "category_name": "日用品", "amount":  8200, "rate": 16 },
  { "category_id": 7, "category_name": "娯楽費", "amount":  8000, "rate": 15 },
  { "category_id": 3, "category_name": "交通費", "amount":  4000, "rate":  8 }
]
```

| 項目 | 内容 |
| --- | --- |
| `amount` | そのカテゴリの対象月の支出合計 |
| `rate` | 支出合計に占める割合（%）。`amount / expense_total * 100` を整数に丸めた値 |

### 受け入れ条件
- 支出カテゴリのみが対象で、**収入カテゴリは含まれない**こと
- 対象月に使われていないカテゴリは、一覧に含まれないこと（0 円の行を出さない）
- 金額の降順（使った順）で並ぶこと。金額が同じなら `category_id` の昇順（並びが実行のたびに入れ替わらないようにするため）
- 支出が 0 件の月は、空配列が返り「支出がありません」と表示されること
- 各カテゴリの `rate` の合計が概ね 100% になること（丸め誤差は許容）
- 画面ではカテゴリ名・金額・割合が表示され、割合が視覚的に分かること

## F-04 月別明細一覧

### 概要
対象月の収支明細を一覧表示する。前月・翌月への切り替えを含む。

### 入力

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| `month` | `yyyy-MM` | 対象月。省略時は当月 |

```
GET /api/entries?month=2026-09
```

検索条件の追加は [F-08](#f-08-検索絞り込み) で定義する。

### 出力
対象月のレコードの配列。`entry_date` 降順、同日なら `id` 降順。

### 受け入れ条件
- 対象月のレコードだけが返ること（月をまたいだデータが混ざらない）
- 各要素にカテゴリ名（`category_name`）と収支区分（`category_type`）が含まれること
- 各行に 日付 / カテゴリ / 金額 / メモ が表示されること
- 支出は金額が赤系、収入は緑系で表示され、区別できること
- 「◀ 前月」「翌月 ▶」で対象月が切り替わり、サマリー・内訳・明細がすべて連動して更新されること
- 対象月が画面に明示されていること（例: 「2026年9月」）
- レコードが 0 件の月は「この月のデータがありません」と表示されること
- 読み込み中はローディング表示、API 失敗時はエラーバナーが表示されること
- `GET /api/categories` でカテゴリ一覧（収入・支出それぞれ）が取得できること

## F-05 収支の追加

### 概要
新しい収支レコードを登録する。

### 入力
```
POST /api/entries
{ "entry_date": "2026-09-25", "category_id": 3, "amount": 1280, "memo": "スーパーで買い物" }
```

### 出力
```
→ 201 Created
{ "id": 12, "entry_date": "2026-09-25", "category_id": 3, "category_name": "食費", "category_type": "EXPENSE", "amount": 1280, "memo": "スーパーで買い物" }
```

### 受け入れ条件
- 「＋ 追加」ボタンで空の入力モーダル（[S-02](./screens.md#s-02-収支入力モーダル)）が開くこと
- 日付の初期値が、**対象月が当月なら本日、それ以外の月ならその月の1日**であること
- カテゴリのセレクトが収入／支出でグループ分けされていること
- 正しい値を送ると 201 が返り、モーダルが閉じて一覧に新しい行が現れること
- **追加後にサマリーとカテゴリ別内訳が再計算されること**（残額が減る）
- 対象月と違う月の日付で登録した場合、その行は現在の一覧に表示されないこと（該当月に切り替えると表示される）
- 必須項目が未入力のとき、400 が返り、該当項目の下にエラーメッセージが表示されること
- 金額に 0 や負数、小数、文字列を入れると 400 になること
- メモが 201 文字以上のとき 400 になること
- 存在しない `category_id` を送ると 400 になること
- 「キャンセル」で何も登録されずにモーダルが閉じること

## F-06 収支の編集

### 概要
既存レコードの内容を修正する。

### 入力
```
PUT /api/entries/12
{ "entry_date": "2026-09-26", "category_id": 4, "amount": 1500, "memo": "訂正" }
```

### 出力
更新後のレコード（200 OK）。

### 収支区分の変更について

**変更後のカテゴリの収支区分（`category_type`）が、変更前と異なる場合は 400 とする。** 支出のレコードを収入カテゴリ（またはその逆）に付け替えることはできない。

理由: 区分が変わると残額の計算結果が大きく動く（支出 30,000 円を収入に変えると残額が 30,000 円増える）のに、画面上は「カテゴリを直しただけ」に見えるため。区分を変えたい場合は、削除して登録し直す。

エラーメッセージ: `支出と収入をまたぐカテゴリ変更はできません`

### 受け入れ条件
- 行の編集ボタンで、既存値が入った状態のモーダルが開くこと
- 編集モーダルのカテゴリ選択に、**元のレコードと同じ収支区分のカテゴリだけ**が表示されること
- 支出のレコードに収入カテゴリを指定して送ると 400 になり、更新されないこと
- 保存すると 200 が返り、一覧の該当行が更新後の値になること
- **更新後にサマリーとカテゴリ別内訳が再計算されること**
- 金額やカテゴリを変更すると、内訳の構成が変わること
- 日付を別の月に変更した場合、その行が現在の一覧から消えること
- [F-05](#f-05-収支の追加) と同じバリデーションが効くこと
- 存在しない ID を更新しようとすると 404 が返ること
- `updated_at` が更新されること

## F-07 収支の削除

### 概要
レコードを削除する。

### 入力
```
DELETE /api/entries/12
```

### 出力
```
→ 204 No Content
```

### 受け入れ条件
- 行の削除ボタンで確認ダイアログ（[S-03](./screens.md#s-03-削除確認ダイアログ)）が表示されること
- 確認ダイアログで「削除する」を選ぶと 204 が返り、一覧から行が消えること

- **削除後にサマリーとカテゴリ別内訳が再計算されること**（残額が増える）
- 存在しない ID を削除しようとすると 404 が返ること

## F-08 検索・絞り込み

### 概要
対象月の中から、さらにカテゴリ・キーワード・期間でレコードを絞り込む。

### 入力

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| `month` | `yyyy-MM` | 対象月 |
| `category_id` | 数値 | カテゴリ ID |
| `keyword` | 文字列 | メモの部分一致（大文字小文字を区別しない） |
| `from` | `yyyy-MM-dd` | 開始日（この日を含む） |
| `to` | `yyyy-MM-dd` | 終了日（この日を含む） |

`from` / `to` を指定した場合は `month` より優先し、**月をまたいだ横断検索**ができる。複数条件は AND。
`from` が `to` より後の日付のときは 400（`開始日は終了日より前の日付を指定してください`）。片方だけの指定は可で、その場合は指定した側だけで絞り込む。`from` と `to` が同じ日なら、その 1 日だけの検索として有効。

空文字（`keyword=` など）は「指定なし」として扱う。画面で入力欄をクリアした状態がそのまま送られてもエラーにしないため。ただし `month` の空文字は、省略とは別に形式不正（400）とする。

**検索条件の形式が不正なときは 400 とする。**

| パラメータ | 不正な場合 | メッセージ | `errors` のキー |
| --- | --- | --- | --- |
| `from` | `yyyy-MM-dd` 形式の実在する日付でない | 開始日の形式が不正です | `from` |
| `to` | 同上 | 終了日の形式が不正です | `to` |
| `category_id` | 数値（0 以上の整数）でない | カテゴリの指定が不正です | `category_id` |

`from` が `to` より後のときの 400 も、`errors` のキーは `from` とする。存在しない `category_id` は形式が正しければエラーにせず、該当なしとして空配列を返す。

**該当が 1,000 件を超える場合は 400 とし、1 件も返さない**（`期間が広すぎます。1,000件を超えるため、期間を絞ってください`）。ページネーションを持たないため、期間を広く取った検索が際限なく行を返さないようにする。

先頭 1,000 件だけを返す「打ち切り」方式は採らない。レスポンスがレコードの配列であるため、受け取った 1,000 件が**ちょうど 1,000 件の該当なのか打ち切られた結果なのかを画面側が判別できず**、「先頭 1,000 件を表示しています」と出すべきかどうかが決められないため。件数の上限を超えたら何も返さないほうが、状態が 1 つに定まる（[F-09](#f-09-一括更新) の一括操作で「全件成功か全件失敗か」としているのと同じ考え方）。

```
GET /api/entries?month=2026-09&category_id=3&keyword=スーパー
GET /api/entries?from=2026-01-01&to=2026-09-30&keyword=家賃
```

### 出力
条件に一致したレコードの配列。

### 受け入れ条件
- 条件を指定しない場合、対象月の全件が返ること
- `category_id` 指定で、そのカテゴリのレコードだけが返ること
- `keyword` 指定で、メモに部分一致するレコードだけが返ること
- `from` / `to` を指定すると、`month` を無視して期間で絞り込まれること（境界日を含む）
- 複数条件の指定が AND で効くこと
- 一致件数が 0 のとき、空配列と「該当するデータがありません」の表示になること
- 「クリア」操作で全条件がリセットされ、対象月の全件表示に戻ること
- **絞り込み中も、サマリーと内訳は対象月全体の値のままであること**（絞り込みは明細一覧のみに作用する）
- 絞り込み中であることが画面上で分かること（該当件数の表示など）
- `from` が `to` より後のとき 400 になること（同じ日なら 400 にならず、その 1 日だけが返る）
- `from` / `to` が実在しない日付や不正な形式のとき、`category_id` が数値でないとき 400 になること
- 存在しない `category_id` を指定したとき、エラーにならず空配列が返ること
- `keyword` に `%` や `_` を含めても、ワイルドカードではなく文字として一致すること
- 空文字のパラメータは指定なしとして扱われること
- 該当が 1,000 件を超える期間検索で 400 が返り、レコードが 1 件も返らないこと
- そのとき画面に「期間が広すぎます」の趣旨のメッセージが出て、直前の一覧が壊れないこと

> サマリーを絞り込みに連動させない理由: このアプリの中心的価値は「その月の予算に対する残額」であり、絞り込んだ一部だけの合計を見せると、残額の意味が変わってしまうため。

### 期間検索でサマリーとの期間がずれる場合の扱い

`from` / `to` は `month` を無視するため、**明細一覧が対象月の外を含む状態**になりうる。このとき上部のサマリーは対象月のままなので、放置すると画面上の 2 つの領域が別の期間を指すことになる。

そこで、`from` / `to` のいずれかが指定され、**その範囲が対象月に収まらない場合**は次のように表示する。

| 領域 | 表示 |
| --- | --- |
| サマリー・カテゴリ別内訳 | 対象月の値のまま変えない。領域に「表示中の期間: 2026年9月」の注記を出し、明細一覧と期間が異なることを明示する |
| 明細一覧の件数表示 | 母数（対象月の件数）を出さず、「該当 3件（2026/01/01〜2026/09/30）」のように**検索期間そのもの**を表示する |
| 「クリア」操作 | 期間条件を外し、対象月の表示に戻す |

受け入れ条件:

- 期間が対象月をまたぐ検索を行ったとき、サマリー領域に対象月を示す注記が表示されること
- そのとき件数表示が「12件中 3件」形式ではなく、検索期間を伴う形式になること
- 期間指定が対象月の中に収まっている場合は、注記を出さず通常の「12件中 3件」形式のままであること

## F-09 一括更新

### 概要
明細一覧で複数のレコードを選択し、カテゴリまたは日付をまとめて変更する。まとめて削除もできる。

レシートを数日分ためて入力した後、日付がすべて入力日になってしまったものを実際の日付に直す、といった修正作業を想定している。

通常時はチェックボックスを表示せず、**「選択」ボタンで選択モードに入ったときだけ**表示する（詳細は [S-01](./screens.md#s-01-ダッシュボード)）。使用頻度の低い機能が常時画面を占有しないようにするため。

### 入力

**一括更新**
```
PATCH /api/entries/bulk
{ "ids": [3, 5, 8], "category_id": 4 }
```
```
PATCH /api/entries/bulk
{ "ids": [3, 5, 8], "entry_date": "2026-09-30" }
```

`category_id` と `entry_date` は任意項目で、指定された項目だけを更新する（両方指定も可、両方未指定は 400）。

**一括削除**
```
DELETE /api/entries/bulk
{ "ids": [3, 5, 8] }
```

1 件ずつ `DELETE /api/entries/{id}` を繰り返すのではなく、**専用のエンドポイントを 1 回だけ呼ぶ**。繰り返し方式では途中で失敗したときに一部だけ削除された状態が残り、しかも削除は取り消せないため。一括更新と同様にトランザクションで囲み、全件削除か 1 件も削除しないかのどちらかにする。

### 収支区分の変更について

一括カテゴリ変更でも、[F-06](#f-06-収支の編集) と同じく**収支区分をまたぐ変更は 400 とする**。選択した行に支出と収入が混在している場合、どちらのカテゴリを指定しても区分の異なる行が生じるため、その時点で 400（`支出と収入をまたぐカテゴリ変更はできません`）を返し 1 件も更新しない。

画面側では、選択行に支出と収入が混在しているときは一括カテゴリの選択を無効化し、理由を添えて操作できないことを示す。

### 出力

**一括更新**
```
→ 200 OK
{ "updated_count": 3 }
```

**一括削除**
```
→ 200 OK
{ "deleted_count": 3 }
```

### 受け入れ条件
- 通常モードではチェックボックスが表示されないこと
- 「選択」ボタンで選択モードに入り、各行にチェックボックスが現れること
- 「完了」ボタンで通常モードに戻り、選択がすべて解除されること
- ヘッダのチェックボックスで表示中の全行を選択／解除できること
- 1 件以上選択すると、選択件数と一括操作バーが表示されること
- カテゴリを選んで適用すると、選択した全行のカテゴリが変わること
- 日付を選んで適用すると、選択した全行の日付が変わること
- 対象月の外の日付に一括変更した場合、その行が現在の一覧から消えること（[F-06](#f-06-収支の編集) と同じ挙動）
- 更新後に選択状態が解除され、一覧・サマリー・内訳が最新化されること
- `ids` が空配列のとき 400 になること
- **`ids` に存在しない ID が含まれるとき 404 になり、1 件も更新されないこと**（トランザクションで全件成功か全件失敗か）
- `category_id` も `entry_date` も指定がないとき 400 になること
- 不正な形式・実在しない日付の `entry_date` を指定したとき 400 になり、1 件も更新されないこと
- 存在しない `category_id` を指定したとき 400 になり、1 件も更新されないこと
- 選択行に支出と収入が混在しているとき、一括カテゴリ変更が 400 になり 1 件も更新されないこと
- 支出だけを選んで収入カテゴリを指定したときも 400 になること
- 一括削除では、確認ダイアログに件数が表示されること
- 一括削除が `DELETE /api/entries/bulk` の 1 リクエストで行われ、`deleted_count` が返ること
- 一括削除で `ids` に存在しない ID が含まれるとき 404 になり、**1 件も削除されない**こと
- `ids` の件数が 500 を超えるとき 400 になること
